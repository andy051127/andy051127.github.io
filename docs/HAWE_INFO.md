## 1. 한 줄 소개

**그룹마다 매일 미션이 열리고, 내가 먼저 답해야 그룹원들의 답을 볼 수 있는 모바일 그룹 앱.**

- 이름 뜻: HA'WE = "하루, 날것 그대로 (today, raw as it is)". 꾸미지 않은 하루를 가볍게 나누는 앱.
- 팀: Sapphire Developers (4인), 사람(검토·git 관리) + AI 코딩 에이전트(구현, 리뷰·디버깅) 분업.
- 플랫폼: iOS(SwiftUI) · Android(Jetpack Compose) 네이티브 앱 + Spring Boot 서버 + Python 비전 서비스.

## 2. 문제와 해결

| | 내용 |
|---|---|
| 대상 | 연인·가족·친구 등 이미 아는 소규모 그룹 (연인 2명, 그 외 최대 6명) |
| 문제 | 소규모 그룹은 연락이 뜸해지고, 일상을 **먼저** 올리는 일이 부담스럽다 |
| 해결 | 서버가 정해진 시각에 가벼운 미션(사진·글·그림)을 열고, **제출해야 서로의 답이 보이게** 한다. "남의 답이 궁금해서" 참여하는 구조 |
| 차별점 | 미션을 사람이 만들지 않고 **그룹 관계·기념일·참여 기록을 반영해 LLM이 생성**하되, 구조는 서버가 정하고 결과는 서버가 검증한다 |

## 3. 핵심 규칙 (서비스 정책 → 서버 규칙)

| 규칙 | 내용 |
|---|---|
| 제출해야 열람 | 내가 답하기 전에는 그룹원의 답·집계가 보이지 않는다. 서버가 `423 Locked`로 강제하고 앱은 블러로 표시만 한다 |
| 자동 발행 | 그룹별 슬롯(하루 1~5개)의 발행/마감 시각에 서버 스케줄러가 미션을 연다 |
| 도장 | 참잘했어요(마감 전 제출) / 지각 / 벌점(안 냄). **저장하지 않고 제출 기록으로 계산** |
| 콕찌르기 | 아직 안 낸 멤버를 재촉하면 알림이 간다 |
| 상호작용 | 스티커 반응(토글), 댓글(@멘션·사진), AI 마스코트 "별"의 댓글 |

## 4. 주요 기능

### 4-1. 사용자 기능
- 이메일 자체 가입·로그인(JWT), 프로필·캐릭터 선택, 회원 탈퇴
- 그룹 생성(관계 5종: 연인·가족·친구·웬수·그저그런사이) / 6자리 초대 코드 미리보기 후 가입 / 후임자 지정 후 나가기
- 미션 3매체(사진·글·그림), 틀 18종 — 삼행시·한 단어 일기·밸런스 게임·빈칸 채우기·색깔 사냥·A를 B로 등
- 결과 피드, 반응, 댓글, 콕찌르기, 알림 목록
- 그룹 달력(미션별 도장), 월간 인사이트(활동 지수·자주 쓴 단어·빠른 제출자·하이라이트)

### 4-2. AI 기능

| # | 기능 | 실행 위치 | 핵심 |
|---|---|---|---|
| 1 | **LLM 미션 생성** | 서버 → LLM | 틀은 서버가 정하고 LLM은 `{문장, 카테고리, 빈칸}`만 생성 → 서버 재검증 → 실패 시 고정 문장 폴백 |
| 2 | **사진–주제 적합도** | 서버(Python FastAPI, CLIP + ONNX fp16) | 사진이 미션 주제에 맞는지 0~1 점수 → "찰떡" 배지·칭찬 (부정 평가는 노출 안 함) |
| 3 | **온디바이스 그림 인식** | 기기(TFLite int8 / Core ML) | 그림 50범주 분류, 그림을 서버로 보내지 않음 |
| 4 | **AI 주제 vs 랜덤 주제 A/B 실험 프레임워크** | 서버 | 블라인드·그룹 내 비교·신뢰구간·표본 부족 경고 |
| 5 | **실시간 AI 그림 추측** | 기기 | 획을 그을 때마다(500ms 디바운스) 추론, EMA·히스테리시스로 말풍선 안정화, 2회 연속 임계 초과 시 "AI가 맞혔어요!" + 경과 시간 |
| 6 | **AI 미션 검색** | 서버(+LLM 질의 확장) | 키워드 → LLM이 연관어 확장(질의만 전송) → Lucene Nori 가중 매칭. "비" → "우산·장마". 멤버 그룹의 마감/제출한 미션만 노출 |
| 7 | **얼굴 자동 모자이크** | 기기(ML Kit / Vision) | 사진 올리기 전 얼굴 검출, 얼굴별 on/off + 수동 영역 지정, 비가역 픽셀화한 비트맵만 업로드 |
| 8 | **멀티 암드 밴딧 틀 선택** | 서버 | 그룹별 계층 Thompson Sampling으로 참여가 잘 나오는 틀을 더 자주 발행, AI 합성 시드를 prior로 콜드스타트 해결 |

### 4-3. 인프라·신뢰 기능

- **블록체인 디지털 배지(업적)**: 서버가 업적을 판정하고 ERC-721 + ERC-5192(Soulbound) 컨트랙트로 배지를 발급한다. 사용자는 지갑·코인·가스비 없이 앱에서 배지와 "블록체인에서 확인" 링크만 본다.
  - 업적 예: 첫 제출, 누적 제출, 얼리버드, 전 틀 달성, 연속 참여(스트릭), 월 개근, 기념일
  - DB가 정본이고 체인은 발급 증명 사본. outbox + 단일 발급 워커 + 영수증 재확인으로 체인 장애가 제출·피드를 막지 않음. 탈퇴 시 소각, 온체인에는 익명 주소만 기록.
  - 체인이 꺼져 있으면 `ISSUED_OFFCHAIN`으로 먼저 발급하고 켜면 이어서 발급(백필).
- **원격 푸시(FCM/APNs)**: 미션 도착·콕찌르기·댓글·멘션 알림을 앱이 꺼져 있어도 받는다. 기존 DB 알림은 앱 안 목록으로 유지.

## 7. 기술적 하이라이트 (면접·포트폴리오 서술용)

1. **서버 주도 제한형 LLM 생성**
   틀·대상·시각은 서버가 결정적 시드로 정하고, LLM은 내용만 채운다. 서버가 길이·금지어·형식(삼행시 제시어 3글자 등)·최근 미션과의 문자 bigram 유사도(≥0.8 거절)를 재검증하고, 실패하면 재시도 후 고정 문장으로 폴백한다. **AI 장애가 미션 발행을 막지 않는다.**
2. **개인정보 최소화**
   LLM에는 날짜, 관계 유형, 틀 정의, 최근 미션 문장, 미션 단위 참여율만 보낸다. 닉네임·그룹 이름·제출 내용은 보내지 않고, `[대상]` 자리표시자를 서버가 표시 시점에 치환한다.
3. **AI를 제출 경로에서 분리**
   `@TransactionalEventListener(AFTER_COMMIT)` + 별도 스레드 풀로 사진 평가·마스코트 댓글을 처리 → 제출이 롤백되면 AI 작업도 안 생기고, 제출 응답은 AI를 기다리지 않는다. 리뷰 행을 `INSERT IGNORE`로 선점해 중복 실행을 막는다.
4. **정책을 서버 접근 제어로 강제**
   "제출해야 열람"을 클라이언트 블러가 아니라 서버 `423 Locked`로 판정. 같은 (그룹·날짜·슬롯) 중복 발행과 한 미션 중복 제출은 DB 고유 제약으로 막는다.
5. **파생 상태는 저장하지 않음**
   도장은 `Stamp.of(submitted, late, closed, memberWhenPublished)`로 제출 기록에서 계산한다. 정합성 문제 자체를 제거.
6. **AI 3종을 위치별로 분리** — LLM(외부 API), 사진 비전(내부 서버), 그림 CNN(기기 안). 비용·지연·프라이버시 요구가 달라서다.
7. **학습–앱 전처리 일치 검증**
   그림 모델 전처리를 명세(`PREPROCESS_SPEC.md`)로 고정하고, 골든 입력 10개로 Python과 Android 출력이 1e-3 이내인지 단위 테스트로 검사한다.
8. **블라인드 A/B 실험을 서비스에 내장**
   `SHA-256(salt|그룹|날짜)`로 결정적 배정, 그룹 내 비교, t-CI·부트스트랩·부호 검정·Wilson CI를 통계 라이브러리 없이 구현.

9. **실시간 추론 안정화**
   획마다 추론하되 500ms 디바운스 + 최신 요청만 남기는 coalescing, 최근 3회 지수이동평균, 1위 교체에 +0.1 히스테리시스, 2회 연속 판정으로 깜빡임·오탐을 줄인다. 로직을 순수 함수로 분리해 JVM 단위 테스트.
10. **프라이버시 우선 얼굴 모자이크**
    검출·변환을 모두 기기에서 하고 **픽셀 자체를 바꾼 비트맵만** 서버에 올린다(오버레이 금지, 약한 블러 대신 비가역 픽셀화). 서버는 블러 여부를 알 필요가 없다.
11. **검색이 잠금 규칙을 우회하지 못하게 설계**
    색인은 서버가 만든 미션 문장만, 노출은 내 그룹의 마감·제출 미션만. LLM에는 질의 문자열만 보내고 출력은 서버가 파싱·검증, 실패 시 원 질의로 폴백. 권한 필터를 핵심 테스트로 둠.
12. **밴딧 콜드스타트와 정직한 한계 표기**
    합성 시드는 영향력을 제한(`K_syn` 이하, 실측이 쌓이면 지수 감쇠)하고 `is_synthetic`으로 실측과 분리 보고. 기존 틀 선택 규칙(매체 순환·어제 매체 제외)은 후보 계산 단계에 그대로 두고 "무작위 선택" 자리만 교체. 결정적 시드로 재현성 유지.
13. **블록체인은 "발급 증명 사본"으로 한정**
    DB가 정본, outbox 패턴 + 단일 워커 + 영수증 재확인으로 재시작·장애에도 중복 발급이 없다. 컨트랙트도 `(주소, 배지)` 중복 mint를 revert해 온체인 멱등. 탈퇴는 소각, 온체인엔 익명 주소만 남겨 개인정보 문제를 회피. "탈중앙 보증"처럼 과장하지 않고 중앙 발급자임을 명시.

## 10. 문제 해결 사례

| 문제 | 원인 → 해결 |
|---|---|
| 비전 서비스 호출이 400으로 실패 | Java HTTP 클라이언트의 h2c 업그레이드 요청을 uvicorn이 거절 → **HTTP/1.1 고정** + 실제 클라이언트로 재현하는 회귀 테스트 추가 |
| 비전 서비스가 무겁고 느리게 시작 | PyTorch 의존 → **ONNX fp16**로 변환, 판정 변화 0임을 5,140쌍으로 검증 |
| 삼행시 입력의 빈 줄 때문에 검증 오류 | 빈 줄을 제외한 3줄로 저장하도록 수정 |
| "풍선으로/풍선을" 같은 조사 어색함 | `KoreanJosa`로 받침에 맞게 서버에서 보정 |
| 중복 이벤트로 AI 리뷰가 두 번 실행될 위험 | `INSERT IGNORE` 선점 + 실패 시 1회 재시도 후 `FAILED` |

## 11. 의사결정 기록 (기능 제거·정책 변경도 포트폴리오 소재)

- 음성 미션 제거(2026-10-12), 슬라이더 미션 제거(2026-10-19), 똥뿌리기·그룹원 제출 알림 제거, 30초 스케치 발행 중단 — 범위를 줄여 품질을 지키는 결정.
- 도장 기준 **미션별**, 피드 잠금 단위 **미션별**, 하루 미션 상한 **5**, 달력은 **그룹별**로 확정 (`docs/BACKEND/CONTRACT_DECISIONS.md`).
- Cordova 하이브리드 앱을 폐기하고 iOS/Android 네이티브로 전환.
- 외부 LLM에 사용자 콘텐츠를 보내지 않는다는 원칙을 신규 기능(검색·밴딧)에도 동일하게 적용.
- 검색은 임베딩·Qdrant 대신 "LLM 질의 확장 + Nori"로 시작(색인 대상이 미션 문장 수천 개 수준이라 벡터 DB가 과함).
- 블록체인은 메인넷 대신 EVM 테스트넷, 양도 불가(Soulbound), 사용자 지갑 비요구로 범위를 한정.
- 얼굴 처리는 서버가 아닌 기기 안에서, 그림 추론도 서버 전송 없이 기기 안에서 수행.

## 12. 한계 (솔직하게 적어 두기)

- 실사용자 연구·배포 데이터 없음 → 참여율·만족도 향상은 주장하지 않는다.
- A/B 실험 프레임워크는 구현됐지만 **실제 실험 결과는 없다**. 문서 속 "AI 92.3% vs 랜덤 50.0%"는 테스트 데이터 예시이므로 성과로 쓰면 안 된다.
- 블록체인 배지는 **중앙 서버가 판정·발급**하므로 서버 없는 보증은 아니다. 테스트넷은 초기화될 수 있고 온체인 기록은 삭제할 수 없어 익명 주소만 쓴다.
- 얼굴 검출은 측면·마스크·작은 얼굴을 놓칠 수 있어 수동 지정을 함께 제공한다(100% 보장 아님).
- 실시간 그림 추측은 모델 범주(약 50개)에 없는 주제를 판정하지 못한다.
- 밴딧의 합성 시드는 LLM의 "믿음"이지 실제 사용자 행동이 아니다. 효과는 실측 데이터가 쌓인 뒤에만 주장한다. 그룹이 작으면(2~3명) 신호가 약하다.
- 단일 EC2 + HTTP 운영, 개발자용 API(`/api/dev/**`) 노출 위험 등 **운영 보안 미완**.
- iOS는 Mac 빌드 확인이 제한적이었다.
- 휴대폰 실기기 추론 시간 미측정.
