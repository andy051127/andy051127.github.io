PROJECT BACKGROUND

왜 주제를 바꿨는가

기존 주제

모바일 LLM-Wiki 앱 — PDF·MD 파일 업로드 시 AI가 정리·분析·단일화하여 나만의 지식 위키를 만들어주는 앱 (9~11주차 진행)

1. 핵심 기능 자체가 불명확

PDF·MD를 올리면 AI가 정리해주는 것이 핵심이었으나, 원하는 퀄리티로 동작하지 않음.
핵심 기능이 제대로 작동하지 않으면 이 프로젝트를 진행할 이유 자체가 없다고 판단.

2. 이미 뛰어난 유사 앱 존재

Notion(문서화·정리), NotebookLM(자료 기반 공부·퀴즈) 등 훨씬 완성도 높은 서비스가 존재.
차별화할 수 있는 포인트를 찾지 못해 만드는 의미 자체가 없다고 판단.

3. AI API 비용·기술 한계

무료 AI API는 사용 한도가 너무 제한적이어서 정상 작동 불가.
사비로 Google AI API를 사용해봤으나 예상 이상의 지출 발생.
프롬프트 엔지니어링 경험 부족으로 기술적 한계도 직면.

이 경험에서 얻은 것

핵심 기능에 비용·기술 리스크가 있는지 사전 검토하는 기획 역량. 실패한 경험 자체가 가장 큰 자산.

새 주제 선택 기준

외부 API 비용 없이 동작 · 학습 범위 내 기술 스택 · 개발자가 직접 쓰고 싶은 앱 = DevFlow

TECH STACK

기술 선택과 그 이유

Flutter / Dart

단일 코드베이스 Android/iOS 동시 지원. Hot Reload로 빠른 UI 반복 개발.

Riverpod

컴파일 타임 타입 안전성. Provider 대비 향상된 테스트 용이성.

SQLite (sqflite)

오프라인 우선 설계. 네트워크 없이 완전한 기능 보장.

Firebase Auth + Firestore

Google 로그인 구현. 로컬 DB 기반 선택적 클라우드 동기화.

flutter_local_notifications

요일/시간 기반 반복 푸시 알림. 정확한 알람 스케줄링.

table_calendar · fl_chart

달력 뷰 일정 관리. 히트맵 & 통계 시각화.
